# 能力雷达方法论

本文档说明能力雷达的设计逻辑，供复用、审计与改进。

## 1. 为什么是"雷达"而不是"报告"

静态报告的问题：信息以周为单位过期，且无法回答"这个趋势在变强还是变弱"。雷达的核心是**动量**——每条信号都有方向（↑↓→），每期与上期逐项对比，读者看到的是趋势的加速度，而不是孤立的快照。

## 2. 双轨设计

| 轨道 | 服务对象 | 核心问题 |
|---|---|---|
| 个人侧 · 能力信号 | 求职者、自由职业、OPC（一人公司） | 什么能力在升值？该把时间投在哪？ |
| 企业侧 · 行业转型信号 | 实体企业决策者、咨询/服务商 | 我这个行业，AI 该怎么转？别人转得怎么样？ |

两轨共用同一套采集与对比机制，但归档维度不同：个人侧按**能力层**归档，企业侧按**行业**归档。

## 3. 信源分层

按可信度从高到低：

1. **一手数据**：招聘平台 JD 关键词、GitHub Trending、招标公告——招聘信息是最真实的"市场需要什么"信号源
2. **权威机构报告**：Stanford AI Index、Lightcast、WEF、LinkedIn、Coursera、PwC、麦肯锡、猎聘、脉脉、科锐国际
3. **社区信号**：Reddit、X、V2EX、即刻、Product Hunt——前沿但需交叉验证
4. **媒体转述**：仅在标注"经引述"的前提下使用，且必须回溯到原始报告名与日期

规则：**所有数据必须标注来源与日期**；无法溯源的数据不写入快照。

## 4. 能力图谱五层框架（个人侧）

- **基础层**（AI 素养/提示词）：门槛性能力，溢价在消退但覆盖在扩大
- **应用层**（Agent 搭建/工作流自动化/AI+数据分析）：当前供需失衡最极端的区域
- **工程层**（Python/部署/云平台）：AI 从实验走向基础设施的执行能力
- **治理层**（AI 伦理与合规）：监管驱动的稳定需求
- **人性层**（批判性思维/验证能力）：AI 无法替代、且因 AI 而增值的能力

框架本身也是被追踪对象：当信号显示分层不再符合市场结构时，框架会被修订并记录修订原因。

## 5. 信号对比机制

每期维护一张**信号级锚点表**：列出当期所有关键信号及其量化状态（如"中国 Agent 工程师岗位 Q1 同比 +310%"）。下期逐项核对：

- **新增**：上期不存在的信号
- **消退**：提及量/增速下降的信号
- **强化**：同口径数据上升的信号

对比必须具体到信号级别，禁止"整体向好"这类泛泛表述。

## 6. 企业侧的特别规则

- **失败教训与成功案例同等权重**——转型决策最缺的是避坑信息
- 案例必须包含三要素才算有效信号：谁做的、用什么方案、投入产出（三者缺一即标注"信息不完整"）
- 行业聚合格式固定：行业 → 本期案例 → 预算/采购信号 → 失败教训

## 7. 人机分工

- **人类**（@MoonHuang0325）：决定监控什么、框架如何分层、哪些信号重要；对最终发布负责
- **AI Agent**：每周定时执行采集、撰写、对比、归档

这一分工本身是本项目的元观点：AI 时代的竞争力 = 人类的判断力 × AI 的执行力。

## 8. 已知局限

- 中文互联网招聘数据散落于各平台，覆盖率受限于公开索引
- 一周周期会错过突发事件的即时性（可在两次周更之间手动触发补更）
- 信号热度 ≠ 对个人/企业的适用性，最终决策仍需结合自身处境
